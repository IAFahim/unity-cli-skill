# Windows and CI notes

## Windows (verified on Unity 7, Windows 11)

- Run shell scripts through Git Bash (`& "C:\Program Files\Git\bin\bash.exe" script.sh`); `bash` is not on the PowerShell PATH. Convert paths with `cygpath -m` before giving them to Unity or a manifest `file:` entry.
- Git Bash with autocrlf gives CRLF working trees. Scripts still run; compare files with `diff --strip-trailing-cr`.
- The editor ships built-in Entities 7.0.0, Collections 7.0.0, Burst 2.0.0, test-framework 1.9.0 and performance 7.0.0; older manifest pins are overridden. Burst 2.0 turns some old patterns into errors (BC1064).
- `Baker.GetComponents<T>()` (array overload) throws "Unknown Type" for a `MonoBehaviour` not registered with the TypeManager; the `List<T>` overload works.
- A fresh project plus the first EditMode run takes a few minutes on a 6-core machine.
- `unity install latest` does not give Unity 7. Use `unity install 7`.
- An agent's PowerShell call starts with the PATH its session started with, so right after installing git, gh or the .NET SDK they are "not recognized". Begin every call with `$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`. A user-scope SDK from `dotnet-install.ps1 -InstallDir $env:LOCALAPPDATA\Microsoft\dotnet` needs that folder (and `%USERPROFILE%\.dotnet\tools` for `ilspycmd`) added to the user PATH plus `DOTNET_ROOT` set; `dotnet-install.ps1` sets neither persistently.
- tl's `ci.yml` line `python3 -m unittest discover -s tests -p test_release_artifacts.py` shells out to `bash`, which is not on the Windows PATH: it errors `FileNotFoundError: [WinError 2]`. Put `C:\Program Files\Git\bin` first on PATH for the gate.
- tl.unity has no `eol` rule in `.gitattributes`, so under Git for Windows' default `core.autocrlf=true` the sync scripts (`eng/sync-tl-core.sh`, `sync-tl-bake.sh`, `sync-parity.sh`) rewrite every synced file with LF and `git status` lists them all as modified. `git diff --ignore-cr-at-eol --stat` shows the real changes; `git add` normalizes the rest. tl itself pins `* text=auto eol=lf`, so its byte budget is the same on Windows.
- A fresh Windows user profile: Unity's first batch run logs `CreateDirectory 'C:/Users/<you>/AppData/Local/Unity/Caches' failed`. Create that folder once.
- Windows PowerShell 5.1 mangles `gh ... -q '.a + " " + .b'` (the inner double quotes are split off as extra arguments). Take `--json` output and pipe it to `ConvertFrom-Json` instead.
- tl's `eng/agent-work` writes Project 6 through `gh project`, which fails with `your authentication token is missing required scopes [read:project]` under `gh auth login`'s default scopes (`gist, read:org, repo, workflow`). Run `gh auth refresh -h github.com -s project` once (interactive).

## Self-hosted runner

- A runner started from a desktop session has a minimal `PATH` (no `~/.local/bin`), so `unity` fails with exit 127. Resolve the CLI explicitly (env override, then `PATH`, then its install dir) and pass `--editor-path`.
- Never pin an editor version in a CI script. Use the newest installed editor, else run `unity install 7 --yes --accept-eula` first. The editor bundles Mono at `<Editor>/Data/MonoBleedingEdge/bin/mono`, which runs `dotnet build` netstandard2.1 dlls, so CI needs no system Mono.
- The runner reuses one workspace: the next queued job overwrites `-logFile` and results files while you read them. Compare timestamps to your job's, or `gh run download` the artifact of your exact run.
- `unity test <project> --editor-path <Editor/Unity> --mode EditMode --filter Class.Method --output /abs/r.xml -- -logFile /abs/l.log`: Unity exit 2 (tests failed) returns CLI exit 8; CLI exit 6 "Test run did not complete" means Unity exited 1 before results, so `grep 'error CS'` the log. With a warm `Library/`, `--filter` reruns one test in about a minute.
- Passing a complex quoted `bash -c "..."` through Windows PowerShell can split the arguments and run only the first command (e.g. only `mkdir lock`) with exit 0. Put chained Unity commands in a real `.sh` file and run `bash file.sh`; then check the XML and log exist. To wait for the shared lock: `until mkdir lock 2>/dev/null; do sleep 30; done` inside that file.
- Inline Python heredocs sent through an agent's Bash tool can turn `\0` or `\1` inside string literals into raw control bytes (git then shows the file as binary, a sed backreference becomes empty). Write such helper scripts to a file first and run them with arguments.
- An agent's Bash call that starts `python - <<'EOF'` with nothing before the terminator (or any interpreter reading an empty stdin heredoc in Git Bash on Windows) opens the interactive REPL on the console instead of exiting: the call hangs until the tool timeout while pyrepl loops on `WinError 123`. Write helper scripts to a file and run `python file.py`.
- A gate script that reruns a failing Unity test pass overwrites the first run's NUnit XML; grep the failed `fullname`s out of it before the rerun, or you cannot tell a known cold-Burst failure from a new one.
- Unity CLI `1.1.0` Windows installs (`7000.0.0a22`): `unity install <ver> --module windows-il2cpp --yes --accept-eula` exits `6` non-elevated and spawns a second UAC prompt inside an elevated shell (timing out as `ELEVATION_CANCELLED`); pass `--no-elevate` inside one Administrator PowerShell (add `--resume` to reuse installers cached in `%APPDATA%\UnityHub\downloads\`).
- Unity CLI `1.1.0` removed `unity auth token` (`error: unknown command 'token'`). After `unity auth login`, activate/renew Personal directly with `unity --no-banner license activate --personal --accept-eula`, and verify via `-createProject` (`Successfully resolved entitlement details` in Editor log; `Unity.Licensing.Client.exe --showEntitlements` can report `No licenses were found` even when licensed).
- Windows runner `keep.cmd` loops: `timeout /t <N>` exits immediately with `ERROR: Input redirection is not supported` in non-interactive Task Scheduler sessions; use `ping -n <N+1> 127.0.0.1 >nul` and prepend Git `bin`, Unity CLI, and `.NET` to `PATH` inside `keep.cmd` (scheduled tasks start with a minimal `PATH`).
- Registering Windows logon tasks non-elevated: `schtasks /create` fails with `Access is denied` and defaults to a 72-hour kill limit (`PT72H`); use `Register-ScheduledTask` (`-AtLogOn`, `-LogonType Interactive -RunLevel Limited`) with `New-ScheduledTaskSettingsSet -ExecutionTimeLimit ([TimeSpan]::Zero) -AllowStartIfOnBatteries -DontStopIfOnBatteries -MultipleInstances IgnoreNew` (`ExecutionTimeLimit=PT0S`).
