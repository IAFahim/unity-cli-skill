# Baking and editor gotchas

- A baking system sees every entity on every incremental bake. Data that only the baking system should see per baker run belongs in `[TemporaryBakingType]`. Its query needs `IncludePrefab | IncludeDisabledEntities`, or prefabs and inactive GameObjects skip it.
- A baker that reads a file must `DependsOn(AssetDatabase.LoadAssetAtPath<Object>(path))`, or editing the file never rebakes.
- Generated system queries usually require every column of the system. Validate an entity against the query, not against what one feature uses.
- Change filters: `chunk.DidChange(ref handle, LastSystemVersion)`, checked before taking a read-write accessor (that marks the chunk changed). The system's own writes don't retrigger it.
- `World.All` includes the Editor's conversion, shadow and staging worlds. Skip `WorldFlags.Conversion | Shadow | Staging` in tools.
- Editor hooks: never call `AssetDatabase.Refresh` inside `OnPostprocessAllAssets`; defer with `EditorApplication.delayCall` (never fires in batch mode). `[InitializeOnLoad]` also runs in asset import workers, so guard with `AssetDatabase.IsAssetImportWorkerProcess()`.
- External processes from the Editor: use `ProcessStartInfo.ArgumentList`, read stderr asynchronously while reading stdout, and `WaitForExit(timeout)`.
- Benchmarks in batch mode: the first run in a fresh Editor is cold (2-3x slower). Run twice, take the later run or a median, and treat ±0.5 ns/entity as noise unless repeated.
- Editor Burst safety checks dominate idle-row benchmarks (1.9 ns with them, 1.3-1.4 without). A job with many type handles pays about 54 ns per chunk in safety checking, so keep rarely used handles out of it. Judge a Unity gate against the .NET number measured on the same machine that day.
- A disturbed run shows in the empty-world step time (13.9 µs against a normal 4.7-9.4): discard runs where it jumps.
- A .NET tool that reflects over a Unity-compiled dll needs its references next to it: copy `Library/ScriptAssemblies/*.dll` and `<Editor>/Data/Managed/UnityEngine/*.dll` into one folder with the dll.
- Test asmdefs compile against a netstandard profile: `MethodImplOptions.AggressiveOptimization` (CS0117) and `System.Runtime.JitInfo` (CS0234) are missing there. Use `(MethodImplOptions)512`, and reflect `JitInfo.GetCompiledMethodCount` off `typeof(object).Assembly`.
- `DOTNET_*` runtime knobs such as `DOTNET_TieredCompilation=0` reach the editor (JIT method counts change), so JIT experiments need no code change.
- In an `ISystem` inside a namespace that contains `Unity` (such as `Tl.Unity`), `SystemAPI.GetBufferTypeHandle`, `GetComponentTypeHandle` and `GetEntityStorageInfoLookup` generate `Unity.Entities...` field types that fail with CS0234; `SystemAPI.GetSingleton` is fine. Cache the handles from `state.Get...` in `OnCreate` and call `.Update(ref state)` in `OnUpdate`. To prove a system's `OnUpdate` is Burst-clean, compile a `[BurstCompile] public static void F(IntPtr sys, IntPtr st) => ((MySystem*)sys)->OnUpdate(ref *(SystemState*)st);` with `BurstCompiler.CompileFunctionPointer` in a test (the shim must be public or you get UAC2017).
- `UNITY_INCLUDE_TESTS` in an asmdef's `defineConstraints` keeps a package assembly out of user projects unless the package is in `testables` (verified on a fresh project from a `file:` path); samples that reference it need the same constraint and `BuildOptions.IncludeTestAssemblies`.
- A source generator shipped in a package (dll labelled `RoslynAnalyzer`, no platform; set it with `PluginImporter` plus `AssetDatabase.SetLabels` from a scratch `-executeMethod`) runs only for the asmdef in its folder and assemblies that reference that asmdef, so an empty marker asmdef next to it makes the generator opt-in (verified on a fresh `file:` project). Asmdef names must be unique even when `defineConstraints` keep one out of the compile ("Assembly with name ... already exists").
- Unity 7: component structs emitted by your own Roslyn source generator compile but are `Unknown Type` at run time, because Entities gets component types from `TypeManagerV2.RegisterComponentType` calls that Unity's generator writes from source files only. Emit a `Register()` method that calls `TypeManagerV2.BeginRegistration`/`RegisterComponentType`, and add a call to it in `__UnityModuleInitialization.Initialize` from an ILPostProcessor. The ILPP asmdef must be named `Unity.*.CodeGen` to get `Unity.CompilationPipeline.Common`. Do not use a `[ModuleInitializer]`: it also runs in tools that load the dll (verified, 7000.0.0a16, IAFahim/tl.unity#18).
- Unity 7 Entities logs `'<System>' creates a query during OnUpdate` as a `LogType.Warning` (only in PlayMode runs) that reaches `Application.logMessageReceivedThreaded`, so a test can scan for it; build queries and type handles once in `OnCreate` (`.Build(ref state)`, then `handle.Update(ref state)`). Building one in `OnUpdate` was a hidden sync point: after the fix, raw reads of job-written counters raced until the reader completed the stored `JobHandle` (verified 7000.0.0a16, IAFahim/tl.unity#21).
