# Baking and editor gotchas

- A baking system sees every entity on every incremental bake. Data that only the baking system should see per baker run belongs in `[TemporaryBakingType]`. Its query needs `IncludePrefab | IncludeDisabledEntities`, or prefabs and inactive GameObjects skip it.
- A baker that reads a file must `DependsOn(AssetDatabase.LoadAssetAtPath<Object>(path))`, or editing the file never rebakes.
- Generated system queries usually require every column of the system. Validate an entity against the query, not against what one feature uses.
- Change filters: `chunk.DidChange(ref handle, LastSystemVersion)`, checked before taking a read-write accessor (that marks the chunk changed). The system's own writes don't retrigger it.
- `World.All` includes the Editor's conversion, shadow and staging worlds. Skip `WorldFlags.Conversion | Shadow | Staging` in tools.
- Editor hooks: never call `AssetDatabase.Refresh` inside `OnPostprocessAllAssets`; defer with `EditorApplication.delayCall` (never fires in batch mode). `[InitializeOnLoad]` also runs in asset import workers, so guard with `AssetDatabase.IsAssetImportWorkerProcess()`.
- External processes from the Editor: use `ProcessStartInfo.ArgumentList`, read stderr asynchronously while reading stdout, and `WaitForExit(timeout)`.
- Benchmarks in batch mode: the first run in a fresh Editor is cold (2-3x slower). Run twice, take the later run or a median, and treat ±0.5 ns/entity as noise unless repeated.
- Editor Burst safety checks dominate idle-row benchmarks (1.9 ns with them, 1.3-1.4 without). A job with many type handles pays about 54 ns per chunk in safety checking, so keep rarely used handles out of it. Judge a Unity gate against the .NET number measured on the same machine that day.
- A disturbed run shows in the empty-world step time (13.9 µs against a normal 4.7-9.4): discard runs where it jumps.
- A .NET tool that reflects over a Unity-compiled dll needs its references next to it: copy `Library/ScriptAssemblies/*.dll` and `<Editor>/Data/Managed/UnityEngine/*.dll` into one folder with the dll.
- Test asmdefs compile against a netstandard profile: `MethodImplOptions.AggressiveOptimization` (CS0117) and `System.Runtime.JitInfo` (CS0234) are missing there. Use `(MethodImplOptions)512`, and reflect `JitInfo.GetCompiledMethodCount` off `typeof(object).Assembly`.
- `DOTNET_*` runtime knobs such as `DOTNET_TieredCompilation=0` reach the editor (JIT method counts change), so JIT experiments need no code change.
- In an `ISystem` inside a namespace that contains `Unity` (such as `Tl.Unity`), `SystemAPI.GetBufferTypeHandle`, `GetComponentTypeHandle` and `GetEntityStorageInfoLookup` generate `Unity.Entities...` field types that fail with CS0234; `SystemAPI.GetSingleton` is fine. Cache the handles from `state.Get...` in `OnCreate` and call `.Update(ref state)` in `OnUpdate`. To prove a system's `OnUpdate` is Burst-clean, compile a `[BurstCompile] public static void F(IntPtr sys, IntPtr st) => ((MySystem*)sys)->OnUpdate(ref *(SystemState*)st);` with `BurstCompiler.CompileFunctionPointer` in a test (the shim must be public or you get UAC2017).
- `UNITY_INCLUDE_TESTS` in an asmdef's `defineConstraints` keeps a package assembly out of user projects unless the package is in `testables` (verified on a fresh project from a `file:` path); samples that reference it need the same constraint and `BuildOptions.IncludeTestAssemblies`.
- A source generator shipped in a package (dll labelled `RoslynAnalyzer`, no platform; set it with `PluginImporter` plus `AssetDatabase.SetLabels` from a scratch `-executeMethod`) runs only for the asmdef in its folder and assemblies that reference that asmdef, so an empty marker asmdef next to it makes the generator opt-in (verified on a fresh `file:` project). Asmdef names must be unique even when `defineConstraints` keep one out of the compile ("Assembly with name ... already exists").
- Unity 7: component structs emitted by your own Roslyn source generator compile but are `Unknown Type` at run time, because Entities gets component types from `TypeManagerV2.RegisterComponentType` calls that Unity's generator writes from source files only. Emit a `Register()` method that calls `TypeManagerV2.BeginRegistration`/`RegisterComponentType`, and add a call to it in `__UnityModuleInitialization.Initialize` from an ILPostProcessor. The ILPP asmdef must be named `Unity.*.CodeGen` to get `Unity.CompilationPipeline.Common`. Do not use a `[ModuleInitializer]`: it also runs in tools that load the dll (verified, 7000.0.0a16, IAFahim/tl.unity#18).
- Unity 7 Entities logs `'<System>' creates a query during OnUpdate` as a `LogType.Warning` (only in PlayMode runs) that reaches `Application.logMessageReceivedThreaded`, so a test can scan for it; build queries and type handles once in `OnCreate` (`.Build(ref state)`, then `handle.Update(ref state)`). Building one in `OnUpdate` was a hidden sync point: after the fix, raw reads of job-written counters raced until the reader completed the stored `JobHandle` (verified 7000.0.0a16, IAFahim/tl.unity#21).
- A package generator can add a generic `ISystem` without Unity's own generator seeing the generated code: write `partial struct Sys<TJobs> : ISystem where TJobs : unmanaged, IJobs` in the package and emit `[assembly: RegisterGenericSystemType(typeof(Sys<GeneratedJobs>))]` plus the `GeneratedJobs` struct into the user assembly. `World.CreateSystem(type)` and default-world creation then work, and the Burst jobs stay as fast as hand-written ones. Generated `unsafe` code also compiled in `Assembly-CSharp` and in an asmdef with `allowUnsafeCode: false` (verified 7000.0.0a16, IAFahim/tl.unity#22).
- Entities Graphics 7.0.0 draws SubScene entities only under an SRP; a `-createProject` project is Built-in, so they move but stay invisible. Set URP headless with `UniversalRenderPipelineAsset.Create(ScriptableObject.CreateInstance<UniversalRendererData>())` saved as assets plus `GraphicsSettings.defaultRenderPipeline` and `QualitySettings.renderPipeline` per level; then a batch Editor without `-nographics` (D3D12) renders them through `Camera.Render` into a RenderTexture for a PlayMode screenshot, after a few frames (verified 7000.0.0a16, IAFahim/tl.unity#22).
- Timeline `+` menu from generated code (7000.0.0a16, IAFahim/tl.unity#24): `TypeUtility.AllTrackTypes` warns "Track type ... appears to be invalid" for every `TrackAsset` subclass whose `MonoScript.FromType` (internal, reflect it) is null or named differently, and adding such a track to a saved `.playable` logs "No script asset for X" (`AddObjectToAsset` needs a persistent script). Roslyn-generated types have no `MonoScript`; emitting one file per class with `AddSource("X.cs")` changed nothing, and an in-memory `MonoScript.Init` hack only silences the first warning. What worked: an Editor step (`[InitializeOnLoad]`, on `EditorApplication.update` after compile) writes one real file per stub into `Assets/<folder>/Editor/` (only for assemblies whose `CompilationPipeline` source files start with `Assets/`), deletes stale ones, then `AssetDatabase.Refresh()`. Make the stub find its data by type name (`Type.GetType`), not by a compile-time reference, so a stale file never breaks the compile. `-quit` batch runs never tick `update`: call the sync method with `-executeMethod`. The menu is purely type-driven (`TimelineContextMenu.BuildNewTracksContextMenu`), there is no extension point for a per-type entry without a type.
- Simulate `+ > X` headless: `-batchmode` without `-quit`, `-executeMethod` subscribes a state machine to `EditorApplication.update` (wait with `timeSinceStartup`, skip while `isCompiling || isUpdating`) and ends with `EditorApplication.Exit(code)`; open the SubScene with `Unity.Scenes.Editor.SubSceneUtility.EditScene` for live conversion; reflect `UnityEditor.Timeline.TimelineHelpers.CreateTrack(TimelineAsset, Type, TrackAsset, string)` (what the menu calls, runs `TrackEditor.OnCreate`) and `TypeUtility.AllTrackTypes()`; count `Application.logMessageReceived` warnings and errors (note the delegate signature is `(string, string, LogType)`). The Edit-mode preview needs `AnimationMode.StartAnimationMode()` around `director.Evaluate()`.
- Timeline marker menu (7000.0.0a16): it lists every non-abstract `ScriptableObject` `IMarker` without `[HideInMenu]` (`TypeUtility.GetUserMarkerTypes()`, label from `[DisplayName]`), and `TimelineHelpers.CreateMarkerOnTrack(type, null, track, time)` (what the menu calls) runs `MarkerEditor.OnCreate`; a `[CustomTimelineEditor]` on a stub base class can delete the stub there and create the real marker: the saved `.playable` then holds only the real marker, no errors (same pattern as track stubs).
- `EditorUtility.RequestScriptReload()` with no changed script reloads nothing (log: `AllLoadedAssembliesAreUnchanged = true`); write a changed `.cs` file and `AssetDatabase.Refresh()` to force a real reload. A project made from the URP template has Enter Play Mode "Reload Domain" disabled, so Play does not reload either. `-enable-alc-leak-detection` printed nothing on Windows batch, even for a deliberate leak (a collectible-assembly `Type` stored in `AppDomain.SetData`), so a missing "assembly load context was not unloaded" line proves nothing there.
- Empty Timeline tracks: the vendored Tl bake throws "empty tracks with duration > 0" for a track with no clips; drop tracks with no baked clips before packing instead of logging an error (a freshly added track is normal).
- An asmdef whose components and systems come only from another package's source generator must still reference `Unity.Entities` (plus `Unity.Burst`, `Unity.Collections`): without it Entities' own codegen skips the assembly and `World.CreateSystem` on a generated generic system throws `Type ... couldn't be found in the SystemRegistry. (This is likely a bug in an ILPostprocessor.)` with 0 compile errors (verified 7000.0.0a16).
- Types in an enclosing namespace beat `using` directives: a test in `namespace A.B.Tests` with `using A.Unity;` binds `typeof(Playback)` to `A.Playback` if that exists, and Entities throws `Unknown Type: A.Playback ... must be registered with the TypeManager`. Write `global::A.Unity.Playback` in such tests.
- A UPM package folder that is also a .NET project can carry its own Unity tests: `Tests/` with an Editor asmdef (`defineConstraints: UNITY_INCLUDE_TESTS`) plus `<Compile Remove="Tests/**" />` in the `.csproj`; run them with only that package in `testables`, so the host package's own test fixtures (which may register clashing types) stay out of the run. Excluding one fixture asmdef instead (`versionDefines` + a `!SYMBOL` constraint) breaks every assembly that references it (CS0246).
- Tl: an `ITlBaker<TClip>` is found only in the clip's own assembly (the mirror calls it). To add components for clips of a pack you do not own (e.g. `PostTransformMatrix` for Motion `Pose`), use a `[WorldSystemFilter(BakingSystem)]` system `[UpdateAfter(typeof(TimelineKindBakingSystem))]` that adds them where the kind state exists (tl.unity 968ce7c).
- Unity `DynamicBuffer` (7000.0.0a16): bytes written past `Length` but inside `Capacity` from a Burst job survive until the next resize, but `EnsureCapacity` copies only `Length` elements; to grow while keeping such scratch data, `ResizeUninitialized(used)` first, then `EnsureCapacity`, then shrink back (Tl sample slots, IAFahim/tl#577).
- A rarely taken branch in a Burst hot loop that reassigns the loop's pointer (`slots = Grow(...)`) or passes a local by `ref` cost about 0.3-0.5 ns/entity in Tl's K bench; leave the fast loop with `return SlowLoop(..., i)` instead. Re-measure the unchanged baseline in the same session before blaming code: the same main read A 7.6-7.8 in the morning and 7.9-8.7 later.
- Tl: `KindEntry` byte 7 (`Owner`) is 0 in .NET but holds the route owner in Unity, so it is not spare; a generated snapshot compiled into its own test project (`tests/Tl.Systems.Tests/Generated/*.g.cs`) must be hand-patched to compile after a Core API change before `TL_UPDATE_SNAPSHOT=1` can regenerate it.
